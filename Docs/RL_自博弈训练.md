# PPO 与训练超参（科普备忘）

> 供复习 / 面试用。配合工作台「② 训练启动 → PPO 超参」面板对照阅读。

## PPO 是什么

**PPO = Proximal Policy Optimization（近端策略优化）**，OpenAI 2017 年提出，Unity ML-Agents 内置算法。属于**策略梯度**家族。

核心思想一句话：**让「做了好事」的动作下次更可能被选，让「做了坏事」的动作更不可能。**

实现上是一张**策略网络**（神经网络）：输入观测（本项目 96 维向量）→ 输出每个动作被选的概率。训练 = 反复调网络权重。

训练是两阶段循环：

```
① 玩（collect）：用当前策略打对局，把 (状态, 动作, 奖励) 攒进经验池
② 学（learn）：用攒好的数据算「哪些动作其实比平均好」，朝那个方向更新权重
③ 回到 ①，换更好的策略再玩、再学……
```

PPO 招牌机制是**裁剪（clip，ε）**：每次更新最多允许新策略偏离旧版本一点。避免「赢一局就把某动作概率翻倍」的大步子导致崩溃——每次只走**近端一小步**，所以训练稳定（这也是 "Proximal" 名字由来）。

「这个动作到底好不好」由 **GAE（广义优势估计）** 计算，它用 `gamma` + `lambd` 把「局部即时好坏」和「整局最终输赢」加权综合。

## 超参各管什么

### ① 收集阶段（玩游戏攒数据）

| 超参 | 通俗解释 | 调大 / 调小影响 |
|---|---|---|
| `buffer_size` 经验池 | 攒够多少条经验才做一次更新 | 大：更新少但统计稳；小：跟环境快但噪声大 |
| `time_horizon` 时序长度 | 每攒多少步就粗略估算一次回报（不必等整局打完） | 大：估计准但吃内存；小：更新快但短视 |
| `gamma` 折扣因子 | 未来奖励打几折；γ=0.99 时 10 步后的 1 分「现值」≈0.9 | 大：有远见；小：只顾眼前。**赢家奖励在终局才给，本项目必须高（0.99）** |

### ② 学习阶段（算梯度、改权重）

| 超参 | 通俗解释 | 调大 / 调小影响 |
|---|---|---|
| `batch_size` 小批大小 | 经验池切小块，每块做一次梯度更新 | 小：更新多、学快但噪声大；大：梯度稳但利用效率低 |
| `num_epoch` 反复学几轮 | 同一批经验重复学几遍 | 大：背太熟易过拟合；小：利用不充分 |
| `learning_rate` 学习率 | 每次更新走多大一步 | 大：快但易震荡发散；小：稳但龟速（3e-4 是常见起点） |
| `epsilon` 裁剪幅度 | 新策略偏离旧策略**最多**多少（PPO 保险丝） | 小：保守稳定；大：激进快但易崩 |
| `lambd` GAE 平滑 | 好坏判断看多长远：0=只看下一步，1=看整局最终输赢 | 0.95 折中，一般不动 |
| `beta` 熵系数 | 给策略撒随机性的奖励，逼它继续探索 | 大：爱试、能走出舒适区；小：快速专注。训练早期偏大后期偏小 |

### ③ 网络结构

| 超参 | 通俗解释 |
|---|---|
| `hidden_units` / `num_layers` | 网络「体积」：每层神经元数 / 层数。越大越聪明但越吃数据。96 维观测 + 复杂动作空间，256×2 层是合理起点 |

### ④ 预算与存档（不影响怎么学，只影响学多久 / 能否续）

| 超参 | 作用 |
|---|---|
| `max_steps` | 总训练预算，到点自动停（bootstrap 默认 50 万步） |
| `summary_freq` | 每多少步打一次日志 / TensorBoard 点 |
| `checkpoint_interval` | 每多少步存一个 `.pt` 存档（崩了能续） |

### ⑤ 自博弈专属（仅 selfplay）

| 超参 | 通俗解释 |
|---|---|
| `window` 幽灵窗口 | 保留最近几个历史版本的自己当对手，防策略崩塌（左右互搏退化） |
| `play_against_latest_model_ratio` | 跟最新版打 vs 跟历史幽灵打的比例。高=内卷快但易崩；低=对手多样、稳 |
| `save_steps` | 每多少步把当前版本「拍照存档」进幽灵池 |

## 调参经验（本项目）

- **bootstrap 阶段**：`beta` 可临时调高，让新手 AI 多探索；会动后再降回。
- **学不动（reward 不涨）**：`learning_rate` 降一档（3e-4 → 1e-4），或加大 `buffer_size`。
- **震荡明显**：降 `epsilon`（0.2 → 0.1）或 `num_epoch`（3 → 2）。
- **整除关系**：`batch_size` 必须整除 `buffer_size`（4096/256=16 ✓），乱填会报错。
- **selfplay**：`window` 越大越稳；`play_against_latest_model_ratio` 别太高，0.3 附近合适。

## 续训 / 覆盖 / 新建

mlagents 对「run-id 已存在」的三种处理：

| 操作 | mlagents 行为 | 网络起点 | 训练后步数 |
|---|---|---|---|
| 同 run-id，不带 flag | **报错拒绝启动**（默认不允许覆盖） | — | — |
| 同 run-id + `--resume` | 加载 `checkpoint.pt` 续训 | 上次的策略 | 上次步数 + 本次 |
| 同 run-id + `--force` | 删除旧目录从零开始 | 随机初始化 | 本次步数 |
| **新 run-id** | 全新训练 | 随机初始化 | 本次步数 |

**为什么说「从 0 重训浪费了之前的学习」？**

- 每 `buffer_size`（4096）步确实会被「吸收」成权重——但**吸收 ≠ 数据还在**。原始对局记录用后即弃（RL 在线学习），重训只能**重新生成**经验，不能「回放」。
- 从 0 重训 = 重新花时间爬升（时间）、重新自己玩一遍去攒体验（体验）、重新随机探索一条不同的路（路径）。
- 续训 = 站在上次的成果上继续走；重训 = 从山脚重新爬一次。

**面板「启动方式」对应**：新建 / 续训（`--resume`）/ 覆盖（`--force`）。续训前**不要改超参**（mlagents 校验 `configuration.yaml` 一致性，改了会报错或行为异常）。

## 一句话总结

**「每次只敢在旧策略附近迈一小步，反复玩、反复学，让好动作概率慢慢涨上去。」**

面试可先抛这句，再展开「收集 → 裁剪更新 → 再收集」的循环。
