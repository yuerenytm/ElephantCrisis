# 游戏质量保障体系（质量工程分工）

> 逻辑对局一套造数（`Tools/sim`）供微观违规检测与宏观平衡统计。

## 仓库目录对照（实现落点）

| 愿景分层 | 代码目录 |
|--|--|
| 游戏本体（Unity） | `Game/` |
| 对局仿真层 | `Tools/sim/` |
| 基线 + AI 异常 + Streamlit | `Tools/logic_qa/` |
| 数值平衡统计 / LLM 顾问 | `Tools/balance_analysis/` |
| 文档 | `Docs/`（根目录） |
| CI | 尚未接入（计划中） |

---

## 一、整体分层架构（5层）

1. **配置层**：YAML 存储游戏规则、角色初始属性、AI 行为参数、AI 异常判定阈值
2. **对局仿真层**：4 名 AI 玩家（象/人/猴/猫）全自动回合调度引擎，生成上万场随机多人对局
3. **日志与基线校验层**
   - 每回合输出结构化 JSON 时序日志（全角色血量、buff、移速、道具、地块、伤害结算记录）
   - Pytest 硬编码规则基线：确定性校验伤害、buff 互斥、背包、濒死、天气等强制规则，100% 精准拦截显性 Bug
4. **AI 异常判别层（核心差异化模块）**：无监督 AI 分析时序对局日志，识别偏离正常分布的异常状态（挖掘未知隐性 Bug）
5. **可视化&工程化层**：Streamlit 操作看板 + GitHub Actions CI 持续回归（CI 尚未接入）

## 二、分工口径

| 模块 | 跑什么 | 职责 |
|--|--|--|
| `sim` LogicSim | 逻辑对局（Game Scripts） | 造 `events.jsonl` |
| `logic_qa/` | 读上述日志 | **微观**：违规 / 异常状态 |
| `balance_analysis` | 读上述日志 | **宏观**：胜率、死亡率、存活… |
