# 架构总纲（一页纸）

> **这份文档是验收标准，不是介绍。**
> 判断"架构是否可用"时，只问下面几条是否成立；不成立就是没做完。

---

## 一、目标的形状

```
        Design/*.csv ──build.py──▶ game_rules.json
                                         │
                        ┌────────────────▼────────────────┐
                        │   Simulation（规则核心，纯 C#）  │
                        │   不认识 Unity / 不认识画面      │
                        └────────────────┬────────────────┘
                                         │ 只通过 IPresentation 要画面
                    ┌────────────────────┴────────────────────┐
                    ▼                                         ▼
        Unity 宿主（人玩）                          dotnet 宿主（跑批）
        App → View → （表现）                       Tools/runner/SimRunner
```

**一句话**：规则只有一份，宿主可以换。换宿主不换规则。

---

## 二、五条验收标准

| # | 标准 | 怎么验 |
|---|---|---|
| 1 | 核心不含 Unity | `dotnet build Tools/runner/CoreCheck/CoreCheck.csproj` |
| 2 | 核心看不见表现层 | 编译期强制（asmdef `ElephantCrisis.Simulation` 引用为空） |
| 3 | 无头模式没有 `if` 分支 | `Simulation/` 里 `IsLogicSim` 出现次数 = 0（注入空实现） |
| 4 | 配置单一真源 | 改 `Design/*.csv` → `build.py` → 游戏行为变；手改 JSON 无意义 |
| 5 | 同种子可复现 | 同种子跑两批，逐局 `winner/reason/full_rounds` 完全一致 |

## 三、三条复杂度预算

改动前先问：**它是否让下面三件事变多？** 是就别做。

| 预算 | 红线 |
|---|---|
| 分层 | 只允许 `App → View → Simulation`；`AI` 只依赖 `Simulation` |
| 数据源 | 配置只有 `Design/*.csv`；配置产物只有 `game_rules.json` |
| 概念 | 一个概念一个名字（例如状态递减时机只有 `TickPolicy`） |

**迁移例外**：允许短期的搬运/中间态，但必须在同一次工作里收干净，不留"两套并存"。

## 四、现在是什么样（2026-11）

| 层 | 文件 | 行数 | 职责 |

| `Simulation/` | 33 | 8,714 | 规则：回合、单位、动作、世界、状态、日志、宿主适配 |

| `Editor/` | 2 | 312 | 仅编辑器：配置构建、元数据导出 |

程序集边界（编译期强制）：

```
ElephantCrisis.Simulation   references: []
ElephantCrisis.View         references: Simulation, Unity.InputSystem
Assembly-CSharp             App / AI / Editor
```

## 五、本质复杂度 vs 意外复杂度

| 本质（删不掉） | 意外（应该消灭） |
|---|---|
| 46 张卡各自的结算差异 | 每张卡一段独立流程（已部分模板化） |
| 7 种地形 × 天气 × 法抗的叠加 | 同一数值散落多处（已收敛进 `GameRulesConfig`） |
| 4 人 FFA 的胜负判定 | 两套参战名单（已合并） |
| 回合内行动顺序 | 四条状态递减路径（已收敛成 `TickPolicy`） |
