# 游戏测开技能补齐方向（P0 / P1）

基于本仓库三件套分工——**逻辑对局一套造数**（`sim`）供 `logic_qa` 微观违规检测与 balance 宏观胜率/死亡率；**实际对局**供 `perf_analysis` 看帧率/美术/演算卡顿——整理秋招 **游戏测开** 建议补齐项。  
原则：优先能挂回本项目、面试常问、可演示；不堆未落地的大词。

---

## 已有基础（不必重复建设）

- 仿真造数 + JSONL 时序日志 + 多进程批量 + 同 seed 复现  
- Pytest 规则基线 + Isolation Forest 可疑对局 + Streamlit 工作台  
- Unity 客户端性能埋点与共现归因  
- 数值一优先级统计 + LLM 调参建议（半自动）  

主叙事：「逻辑造数 → 微观断言/异常 → 宏观平衡 → 实机性能归因」。补齐重点是 **工程交付感** 与 **测开常见短板**。

---

## P0：优先补齐（面试高频，易接到现有项目）

### 1. CI（持续集成；CD 可弱化）

**做什么**

- 用 GitHub Actions（或同类）在 push / PR 时自动执行：  
  - `logic_qa` 的 Pytest  
  - 小规模仿真 + 基线校验（烟雾级场次即可）  
- 失败红灯；报告 / 日志以 artifact 上传  

**为何优先**

- 证明测试嵌进协作流程，而不只是本地脚本  
- 游戏测开很少强求「自动上架商店」式 CD；**CI 拦回归** 即可讲清楚  

**挂回本项目**

- 入口：`Tools/logic_qa`（pytest + `run_baseline` / 短 `run_qa_pipeline`）  
- 简历表述示例：「MR 自动回归逻辑基线，失败阻断合并」  

**CD 怎么讲**

- 能区分 CI vs CD；了解测试服热更 / 包体分发即可  
- Unity 正式上架式 CD 不作秋招必做项  

---

### 2. 接口 / 协议测试意识（轻量即可）

**做什么**

- HTTP/JSON 请求—响应断言，或本地 mock + 简单契约校验  
- 练习异常包、错误码、超时  

**为何优先**

- 游戏测开常见：登录、匹配、战斗校验、配置下发  

**挂回本项目**

- 不必先上完整服务端；可单独做小 demo，或对「配置下发 / 本地 API」做断言示例  

---

### 3. 测试设计能力（底盘，不只是工具）

**做什么**

- 等价类、边界值、状态迁移、正交思路  
- 结合本游戏：濒死、隐匿、熔岩、真伤、天气与 Buff 互斥等设计用例  

**为何优先**

- 面试常问「这个技能怎么测」；工具是加分，用例思维是底盘  

**挂回本项目**

- 把基线规则整理成「用例 → 断言 → 日志证据」对照表  
- 用同 seed 复现讲清步骤  

---

### 4. 缺陷闭环案例（1～2 个完整故事）

**做什么**

- 用 **Game LogicSim** 批跑 + 基线 / 回放，自己发现问题 → 同 seed 复现 → 根因 → 修复 → 回归通过  
- **禁止编造案例**；面试官会追问日志细节与判断过程  

**为何优先**

- 测开核心产出是「找到并推着修完」，不是只跑流水线  

**挂回本项目**

- 造数：`Tools/sim/scripts/run_batch.py`（Unity 真源）  
- 检测：`Tools/logic_qa`；修复落在 `Game/Assets/Scripts`  
- 简历只写自己亲手跑通的闭环

## P1：差异化加分（与现有平台顺延）

### 5. 客户端自动化（Unity）

- UI 脚本 / 命令行无头进战斗并断言状态或战报  
- 或固化 `-perfAuto` 类自动对局 + 退出码 / 产物检查  
- 体现「能碰客户端」，游戏测开加分项  

### 6. 性能与稳定性补强

- 在现有卡顿共现之上：长时间 soak、内存曲线、简单帧率 / hitch 门槛  
- 能讲清 Profiler / 日志 / 复现路径  
- 可选：CI 或定时跑短 session 冒烟（不必每 PR 全量）  

### 7. 配置与数值变更回归

- YAML / 配表字段范围、引用完整性校验  
- 「改表 → 仿真 → 胜率等指标 diff」报告（本仓库已有统计与顾问雏形）  
- 很像业务测开日常：防配表改炸  

### 8. 基础 SQL / 日志排查

- 查流水、按错误码聚合、关联一次失败对局  
- 服务端向测开几乎必问的入门能力；可用本地 SQLite / 示例库练习

## P2：有余力再做（不建议为简历硬上）

| 方向 | 说明 |
|--|--|
| CD 完整落地 | 自动部署测试服等；懂概念即可 |
| Lua / 双端数值对拍 | 已用 Unity LogicSim 作真源批跑，一般不再需要 Python 对拍 |
| 弱网 / 多机型矩阵 | 有设备再做 |
| 重型测试中台 | Streamlit 已够演示；不必先上权限/队列大系统 |

---

## 建议落地顺序

| 顺序 | 事项 | 简历可写方向 |
|--|--|--|
| 1 | GitHub Actions：pytest + 小批量基线 | MR 自动回归逻辑基线 |
| 2 | 整理 1 个完整缺陷案例 | 逻辑缺陷定位与修复闭环 |
| 3 | 配表校验或平衡报告前后 diff | 数值 / 配置变更回归 |
| 4 | （可选）Unity 无头或 `-perfAuto` 冒烟 | 客户端性能 / 冒烟自动化 |

---

## 表述注意

- **主差异化**仍是：仿真造数、双层逻辑检测、客户端性能归因、数据驱动平衡建议。  
- **CI** 是把上述能力焊进工程流程，不是替代项目主线。  
- 简历只写已落地或一周内能演示的；P2 未做不要写成「已实现」。
