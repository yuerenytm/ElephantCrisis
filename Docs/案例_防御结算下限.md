# 案例：防御结算可为负导致物伤超过攻击（真实缺陷闭环）

> 状态：**已修复**  
> 发现方式：Game LogicSim 批跑 + `logic_qa` 基线  
> 性质：偶发组合态（多条减防叠加），真人手测极难稳定复现  

---

## 1. 现象

基线报告出现：

```json
{
  "rule_id": "dmg_physical_bound",
  "severity": "critical",
  "t": 322,
  "message": "物伤 dealt(12) 不在 [0, raw=11]",
  "context": {
    "target": "human",
    "actor": "elephant",
    "match_id": "match_13"
  }
}
```

含义：日志里一次**物理伤害**的实际扣血 `dealt` 大于进攻方攻击 `raw`（12 > 11）。  
基线假定物伤满足 `0 ≤ dealt ≤ raw`（即防御不应为负）。

---

## 2. 证据（同局日志）

对局：`Tools/sim/output/match_13/events.jsonl`

```text
t=320  damage  elephant→human  physical  raw=11 dealt=9   via=shoot
t=321  status  human  poison  apply
t=322  damage  elephant→human  physical  raw=11 dealt=12  via=shoot
```

同一段内人先吃到中毒（防 −2 等），随后一枪 `dealt=12 > raw=11`。  
结合雨天 / 跌倒 / 中毒等减防来源，结算防御可被叠到 **负数**，于是：

```text
dealt = max(0, 攻 − 防) = 11 − (−1) = 12 > raw
```

---

## 3. 根因

| 层级 | 说明 |
|------|------|
| 代码 | `CurrentDef` 直接返回各修正之和，**未做下限** |
| 规则意图 | 设计上不打算做「破防」；物伤不应超过攻击 |
| 为何偶发 | 需多条减防同时生效，手测覆盖成本高；批跑 + 硬断言才能稳定撞上 |

---

## 4. 产品决策

评估两种方向后选择 **A**：

- **A. 防御结算下限 0**（采用）——不做破防语义，多余减防不再把防打成负数  
- B. 正式允许负防并做成破防状态 —— 不在当前设计预期内  

---

## 5. 修复

| 项 | 内容 |
|----|------|
| 代码 | [`UnitActor.CurrentDef`](../Game/Assets/Scripts/Units/UnitActor.cs)：`Mathf.Max(0, Def)` |
| 规则 | [`规则_游戏概述与规则.md`](./规则_游戏概述与规则.md)、[`规则_卡牌与状态.md`](./规则_卡牌与状态.md) 写明防御结算下限 0 |
| 回归 | 同流水线复跑；`dmg_physical_bound` 因「负防导致 dealt>raw」的路径应不再出现（基线规则本身保留） |

---

## 6. 测开叙事（面试可用）

1. **造数**：Unity Game LogicSim 批量对局出 `events.jsonl`  
2. **检出**：基线 `dmg_physical_bound`（critical）  
3. **定位**：对日志与减防状态，确认负防御叠加  
4. **决策**：与设计对齐，选下限 0 而非破防  
5. **修复 / 回归**：改结算 + 同步规则文案，复跑验证  

工具链价值：把「鬼知道打多少局」的组合态，变成可复现、可断言、可回归的缺陷闭环。
